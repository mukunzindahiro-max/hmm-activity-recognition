# Human Activity Recognition with Hidden Markov Models

Formative 2: recognising **standing, walking, jumping and still** from smartphone
accelerometer and gyroscope data, using a Hidden Markov Model implemented from
scratch in NumPy.

## Data collection

| Item | Value |
|---|---|
| App | Sensor Logger 1.68 (iOS) |
| Device | iPhone 13 (iOS 26.5) |
| Sensors | Accelerometer (x, y, z), Gyroscope (x, y, z), Gravity (x, y, z) |
| Sampling rate | 100 Hz (10 ms interval) |
| Training clips | 80 (20 per activity, 8.7 – 10.0 s each) |
| Test sessions | 2 continuous sessions of about 40 s (all four activities) |

Recording time per activity (training):

| Activity | Clips | Total duration |
|---|---|---|
| Standing | 20 | 193.7 s |
| Walking | 20 | 199.7 s |
| Jumping | 20 | 186.8 s |
| Still | 20 | 199.7 s |

Clips longer than 10 s are trimmed equally from both ends, which also removes the
phone-tap at the start and end of each recording.

## Preprocessing and windowing

| Step | Setting | Reason |
|---|---|---|
| Resampling | uniform 100 Hz grid (linear interpolation) | removes timestamp jitter and harmonises devices with different sampling rates onto one rate |
| Low-pass filter | 4th-order Butterworth, 20 Hz, zero-phase | human motion is below 20 Hz; removes high-frequency sensor noise without shifting the signal in time |
| Edge trim | 0.5 s at each end of training clips | removes the tap on the phone screen when starting and stopping a recording |
| Window | 2.0 s = 200 samples | covers at least 2 full walking or jumping cycles (about 1.5 – 2.5 Hz) and gives a 0.5 Hz FFT resolution |
| Overlap | 50 % (step of 100 samples) | gives one observation per second for the HMM and smooths transitions |

| Set | Recordings | Windows |
|---|---|---|
| Training | 80 clips | 577 (standing 145, walking 149, jumping 135, still 148) |
| Test `mixed_01.csv` | 1 session | 39 |
| Test `mixed_02.csv` | 1 session | 39 |

## Feature extraction

14 features per 2 s window (9 time-domain, 5 frequency-domain from the FFT):

| Domain | Features |
|---|---|
| Time | `acc_mag_mean`, `acc_mag_std`, `acc_rms`, `acc_sma`, `acc_ptp`, `gyr_mag_std`, `gyr_sma`, `acc_corr_yz`, `tilt_deg` |
| Frequency | `vert_dom_freq`, `vert_spectral_energy`, `vert_spectral_entropy`, `vert_band_ratio`, `gyr_dom_freq` |

The frequency features use the vertical acceleration (acceleration projected on the
gravity direction), so the step and jump rhythm (about 2 Hz) is independent of how
the phone is held. Magnitude and energy features are log10-transformed, then all
features are Z-score normalised with the mean and standard deviation of the training
windows only.

## Hidden Markov Model

Implemented from scratch in NumPy (`src/hmm.py`):

| Component | Implementation |
|---|---|
| Hidden states | standing, walking, jumping, still |
| Observations | 14-dimensional normalised feature vector per window |
| Emissions | Gaussian per state, diagonal covariance, variance floor 0.01 |
| Training | Baum–Welch (EM) with log-space forward–backward, stops when the log-likelihood improves by less than 1e-4 |
| Decoding | Viterbi (log space) |

State means are seeded from the labelled training windows so each hidden state keeps
its activity meaning; π, A and the covariances start uniform/pooled and are learned by
Baum–Welch. The forward, Viterbi and posterior computations are verified against
brute-force enumeration in the notebook.

```bash
python -m src.train
```

## Repository structure

```
data/
  raw/                     cleaned, labelled training clips (<activity>_<NN>.csv)
  test/                    unseen continuous test sessions (mixed_<NN>.csv)
  processed/               normalised features, normalisation statistics and the trained model
  dataset_summary.csv      samples, duration and sampling rate of every file
src/
  preprocessing.py         resampling, filtering, edge trimming and windowing
  features.py              time and frequency features, Z-score normalisation
  hmm.py                   Gaussian HMM: forward-backward, Baum-Welch, Viterbi
  train.py                 model initialisation, training and saving
plots/                     figures generated by the notebook
har_hmm.ipynb              end-to-end notebook
build_dataset.py           converts the Sensor Logger exports into the clean CSV files
requirements.txt
```

## CSV format

| Column | Description |
|---|---|
| `time` | Unix timestamp (ns) from the phone |
| `seconds_elapsed` | seconds since the first sample |
| `acc_x`, `acc_y`, `acc_z` | user acceleration, gravity removed (m/s²) |
| `gyr_x`, `gyr_y`, `gyr_z` | angular velocity (rad/s) |
| `grav_x`, `grav_y`, `grav_z` | gravity vector (m/s²) |
| `fs` | device sampling rate (Hz) |
| `activity` | ground-truth label |
| `participant`, `device` | who recorded the clip and on which phone |

The test sessions follow these activity orders:

- `mixed_01.csv`: standing → walking → jumping → still
- `mixed_02.csv`: walking → still → jumping → standing
